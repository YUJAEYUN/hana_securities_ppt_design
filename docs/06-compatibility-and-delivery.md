# 6. 호환성 검증과 최종 인수

## 목적

구현물이 특정 작업 세션이나 AI 도구에 묶이지 않고, 새 환경에서 문서만 따라 재현되는지 확인한다.

## 환경 호환성

### 공통 실행 경로

- 표준 Python 가상환경을 기본으로 안내한다.
- 의존성은 `requirements.txt`로 설치한다.
- 스크립트는 표준 CLI 인자를 사용한다.
- 경로는 Windows와 POSIX 모두에서 동작하도록 `pathlib`로 처리한다.
- AI 벤더 전용 API나 MCP 호출은 필수 경로에 두지 않는다.
- Windows와 macOS에서 각각 `font_preflight.py`를 실행해 해당 플랫폼용 CI/하나서체 파일과 설치 상태를 검사한다.
- 폰트 자동 설치는 기본 동작으로 제공하지 않고 수신자 PC에도 설치를 요구하지 않는다. 기본적으로 사용된 글리프만 번들 폰트에서 서브셋으로 임베딩하고, PowerPoint 재열기와 폰트 미설치 렌더 검증에 실패할 때 정적 PPTX를 생성한다. 모든 실행에서 PDF를 시각 기준본으로 함께 생성한다.

### Codex

- 스킬 폴더의 `SKILL.md`와 `agents/openai.yaml` 형식을 검증한다.
- 저장소 작업 지침이 필요할 때 `AGENTS.md`가 올바르게 적용되는지 확인한다.
- 스킬 초기화와 최종 검증에는 `skill-creator` 제공 스크립트를 사용한다.

### Claude Code

- 구현 시점의 공식적인 스킬/명령 인식 위치와 frontmatter 요구사항을 확인한다.
- 공통 실행 본문을 유지하면서 Claude Code가 요구하는 설치 또는 참조 방식을 문서화한다.

도구별 동작은 변경될 수 있으므로 실제 구현 단계에서 공식 문서를 재확인한다. 확인되지 않은 설치 경로나 트리거 방식을 현재 문서에서 단정하지 않는다.

## 재현성 시나리오

깨끗한 환경에서 다음 순서로 검증한다.

1. 저장소를 체크아웃한다.
2. 가상환경을 만들고 의존성을 설치한다.
3. 현재 OS에 맞는 번들 폰트 파일, 임베딩 권한과 설치 상태를 사전 검사한다.
4. 임베딩 가능한 경우 사용된 글리프만 포함한 `embed-preferred` 출력을 만들고, PowerPoint의 임베딩 상태와 폰트 미설치 렌더 결과를 검증한다. 불가능하거나 검증에 실패하면 정적 PPTX를 생성한다.
5. 샘플 5개 이상으로 토큰을 추출한다.
6. 사람이 `brand.json`과 디자인 토큰 요약을 검토한다.
7. 정본 `deck_spec.json`에서 샘플 PPTX와 PDF를 생성한다.
8. 구조 품질검사를 실행한다.
9. PowerPoint 또는 대체 렌더러로 모든 슬라이드를 PNG로 렌더링한다.
10. 이미지 자동검사와 비전 에이전트 검사를 실행한다.
11. 고의 구조·시각 이탈 픽스처가 실패하는지 확인한다.
12. Claude Code와 Codex에서 각각 스킬 지침을 따라 같은 절차를 수행한다.

## 최종 Definition of Done

- [ ] 샘플 PPTX 5개 이상에서 `design-tokens.md`와 `brand.json` 생성
- [ ] 표지, 목차, 텍스트+불릿, 비교, 클로징 생성
- [ ] 색상과 폰트의 고의 이탈 검출
- [ ] Windows용·macOS용 CI/하나서체 원본이 저장소에 포함되고 `brand.json` 경로와 일치
- [ ] Windows와 macOS에서 폰트 사전 검사가 자산 누락과 미설치를 올바르게 구분
- [ ] CI/하나서체가 설치되지 않은 수신 환경에서 서브셋 임베딩된 PPTX 또는 정적 PPTX가 기준 PDF와 합의된 시각 허용 오차 이내로 표시
- [ ] 사용된 모든 폰트 패밀리·스타일이 PowerPoint에서 임베딩 상태로 확인되고 웹 PowerPoint 열람에서도 대체 폰트로 바뀌지 않음
- [ ] `restyle-only`, `hana-refine`의 변경 범위와 대화형 확인 절차가 동작
- [ ] 조사·팩트 수집·최초 초안 생성은 상위 에이전트가 담당하고 이 스킬은 완성된 초안만 인수
- [ ] 제공된 출처에 없는 새 사실을 추가하지 않고 부족한 근거는 상위 에이전트에 반환
- [ ] 첨부 PPTX의 텍스트·표·차트·이미지를 추출하고 선택 모드에 맞게 변환
- [ ] 로고 규정 검사와 텍스트 오버플로우 경고 제공
- [ ] PowerPoint 우선, LibreOffice 대체 순서로 모든 슬라이드 PNG와 렌더 manifest 생성
- [ ] 이미지 검사에서 잘림·겹침·여백 부족·정렬 이탈·밀도 이상 검출
- [ ] contact sheet와 슬라이드별 비전 평가 JSON 생성
- [ ] 사용자의 모든 후속 변경 요청이 `deck_spec.json` 수정과 전체 재생성으로 처리됨
- [ ] 렌더러가 없는 결과는 `partial`로 보고되고 최종 `pass`로 오인되지 않음
- [ ] `SKILL.md`만으로 신규 사용자가 작업 재현
- [ ] Claude Code와 Codex 설치·트리거 차이 문서화
- [ ] `SKILL.md`와 `AGENTS.md` 공통 지침 동기화 검증
- [ ] 자동 수정 3~5회 후 사람 확인 정지
- [ ] `quick_validate.py`로 스킬 구조 검증
- [ ] 대표 스크립트와 테스트 전체 통과

## 현재 다음 액션

최신 상태와 다음 액션은 `project-state.json`에서 관리하고 [STATUS.md](STATUS.md)에 자동 반영한다. 현재 스킬 메타데이터, 폰트·CI 원본, HFG IR 후보 토큰과 기준 이미지는 존재하지만 PPT 인수·후처리·생성·검사 스크립트는 미구현이다. 하나증권 리서치센터 자료 하나는 예외로 제외했으므로 대표성이 확인된 하나증권 샘플, CI 변환본과 사람의 브랜드 승인이 우선 필요하다.
