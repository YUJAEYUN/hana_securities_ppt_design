# 4. 스킬 지침과 PPT 생성기

## 목적

확정된 `brand.json`과 `layout-patterns.md`를 사용해 5종 이상의 슬라이드를 생성하고, Claude Code와 Codex가 같은 절차를 재현하도록 지침을 작성한다.

## `build_deck.py` 구현 순서

1. 입력 콘텐츠 스키마와 CLI를 정의한다.
2. 새 프레젠테이션과 화면비를 초기화한다.
3. 공통 요소 생성 함수를 만든다: 제목, 로고, 페이지 번호, 구분선, 텍스트 스타일.
4. 표지, 목차, 텍스트+불릿, 비교, 클로징 빌더를 각각 분리한다.
5. 슬라이드별 콘텐츠 검증과 넘침 사전 경고를 추가한다.
6. 샘플 콘텐츠로 `examples/sample_output.pptx`를 생성한다.

## 필수 불변 조건

- 색상, 폰트, 여백, 로고 경로를 Python 코드에 직접 쓰지 않는다.
- 각 슬라이드 생성 함수는 시작 시 `brand.json`을 새로 읽는다.
- 기본 효과 설정은 애니메이션, 그림자, 그라데이션 모두 꺼짐이다.
- 옵션 효과는 브랜드 규칙과 충돌하지 않을 때만 명시적으로 켠다.
- 입력이 레이아웃 수용량을 넘으면 조용히 축소하지 않고 경고 또는 실패한다.

## `SKILL.md` 내용

- YAML frontmatter에는 `name`과 포괄적인 트리거 설명만 둔다.
- Claude Code와 Codex 양쪽에서 사용 가능하다는 점을 명시한다.
- 환경별 설치 위치와 호출 방법을 짧게 안내한다.
- 필요한 참조 문서를 언제 읽어야 하는지 직접 연결한다.
- 분석, 생성, 검사, 제한 반복의 순서를 명령형으로 설명한다.
- 폰트 임베딩 한계와 설치된 사내 폰트 전제를 명시한다.
- 특정 벤더 전용 도구 호출을 필수 절차로 넣지 않는다.
- 본문은 간결하게 유지하고 상세 규칙은 `references/`로 보낸다.

## `AGENTS.md` 동기화

`SKILL.md`의 공통 실행 본문을 정본으로 삼아 `AGENTS.md`를 생성한다. 생성 파일에는 직접 편집 금지 표식을 넣고, 동기화 테스트를 추가한다. 플랫폼별 심볼릭 링크 권한 문제를 피하기 위해 심볼릭 링크는 기본안으로 사용하지 않는다.

## 테스트

- 5개 필수 빌더가 각각 최소 한 장을 생성한다.
- 생성 파일을 `python-pptx`로 다시 열 수 있다.
- 코드에서 허용되지 않은 색상 hex가 직접 사용되지 않았는지 검사한다.
- 슬라이드 사이에 `brand.json`을 바꾼 테스트에서 다음 슬라이드부터 값이 반영된다.
- 효과 옵션의 기본값이 모두 꺼져 있다.

## 완료 조건

- 표지, 목차, 텍스트+불릿, 비교, 클로징 생성이 가능하다.
- 샘플 출력이 생성되고 열림 검사를 통과한다.
- `SKILL.md`만으로 설치부터 생성까지 재현할 수 있다.
- `AGENTS.md`와 공통 본문의 동기화가 자동 검증된다.
