# 4. 스킬 지침과 PPT 생성기

## 목적

다른 에이전트나 PPT 생성 스킬이 만든 PPTX 또는 구조화된 초안을 입력받고, 확정된 `brand.json`, `layout-patterns.md`, `hana-tone-guide.md`를 사용해 하나증권 스타일 결과를 만든다. 이 스킬은 범용 조사와 최초 초안 생성을 담당하지 않는다.

## 후처리 워크플로

### `restyle-only`: 기존 초안의 디자인만 개선

- 원문, 수치, 고유명사와 표·차트 데이터를 보존한다.
- 브랜드 색상, 폰트, 여백, 정렬, 로고와 레이아웃만 변경한다.
- 콘텐츠가 레이아웃에 맞지 않으면 임의로 삭제하지 않고 슬라이드를 분할하거나 예외 레이아웃을 사용한다.
- 페이지 수가 달라지면 원본 슬라이드와 결과 슬라이드의 대응표를 남긴다.

### `hana-refine`: 하나증권식 말투와 디자인 함께 개선

- 제공된 초안의 사실, 수치, 고유명사와 출처를 유지한다.
- 사용자 요청 범위에서 제목, 문장, 분량, 정보 계층, 슬라이드 순서와 시각화를 하나증권식으로 개선한다.
- 의미가 달라질 수 있는 변경은 계획을 먼저 보여주고 확인받는다.

말투와 내용 변경 요청이 없으면 `restyle-only`, 말투·요약·흐름 개선 요청이 있으면 `hana-refine`을 사용한다. 초안이 없으면 상위 에이전트나 다른 PPT 생성 스킬이 조사와 초안을 먼저 만들게 하고, 완료된 초안을 다시 이 스킬에 전달한다. 원본 PPTX는 덮어쓰지 않는다.

## 첨부 PPTX 처리 순서

1. `ingest_deck.py`로 텍스트, 표, 차트, 미디어, 발표자 노트와 슬라이드 구조를 추출한다.
2. `upstream-handoff.md`에 따라 목적, 청중, 필수 보존 항목과 출처 목록이 전달됐는지 확인한다.
3. 사용자 요청에서 `restyle-only` 또는 `hana-refine`을 결정한다.
4. `hana-refine`이면 말투·구조 변경 계획을 작성해 사용자 확인을 받는다.
5. `restyle_deck.py` 또는 `build_deck.py`로 결과를 생성한다.
6. 폰트 전달 정책을 적용하고 구조 품질검사를 실행한다.
7. `render_slides.py`로 슬라이드별 PNG를 생성한다.
8. `visual_check.py`로 결정적 이미지 검사를 실행하고 contact sheet를 만든다.
9. 에이전트가 `visual-review-rubric.md`에 따라 개별 PNG와 contact sheet를 시각 평가한다.
10. `deck_spec.json`, 원본 초안, 출처 목록, 변경 계획, PPTX, PDF, 렌더 이미지와 검사 리포트를 함께 보존한다.

SmartArt, OLE, 복잡한 차트, 수식과 미디어는 직접 편집 가능한 Office 객체로 유지할 필요가 없다. 추출 가능한 내용과 시각을 정본에 기록하고 결과에서는 이미지 또는 정적 요소로 평면화한다. 원본 객체를 해석하지 못하면 조용히 삭제하지 않고 사용자에게 경고한다.

## `build_deck.py` 구현 순서

1. 입력 콘텐츠 스키마와 CLI를 정의한다.
2. 새 프레젠테이션과 화면비를 초기화한다.
3. 공통 요소 생성 함수를 만든다: 제목, 로고, 페이지 번호, 구분선, 텍스트 스타일.
4. 표지, 목차, 텍스트+불릿, 비교, 클로징 빌더를 각각 분리한다.
5. 슬라이드별 콘텐츠 검증과 넘침 사전 경고를 추가한다.
6. 샘플 콘텐츠로 `examples/sample_output.pptx`를 생성한다.

## 필수 불변 조건

- 색상, 폰트, 여백, 로고 경로를 Python 코드에 직접 쓰지 않는다.
- 각 슬라이드 생성 함수는 시작 시 `brand.json`을 새로 읽는다.
- 기본 효과 설정은 애니메이션, 그림자, 그라데이션 모두 꺼짐이다.
- 옵션 효과는 브랜드 규칙과 충돌하지 않을 때만 명시적으로 켠다.
- 입력이 레이아웃 수용량을 넘으면 조용히 축소하지 않고 경고 또는 실패한다.
- 덱 생성 전에 `font_preflight.py`를 실행한다. 현재 OS용 자산이 없거나 설치·임베딩·정적 변환 중 가능한 전달 경로가 하나도 없으면 생성하지 않는다.
- 기본 폰트 전달 정책은 `embed-preferred`이며, 임베딩 결과를 검증하지 못하면 경고 없이 성공 처리하지 않는다.
- `restyle-only`에서 원문과 데이터 잠금을 위반하면 결과 생성을 실패시킨다.
- `hana-refine`에서 제공된 초안과 출처에 없는 새 사실을 추가하면 결과 생성을 실패시킨다.
- 이 스킬은 웹 검색이나 외부 자료 조사를 필수 실행 단계로 포함하지 않는다. 추가 조사가 필요하면 상위 에이전트에 반환한다.
- 사용자가 PowerPoint에서 직접 편집할 수 있는지는 검사하거나 보장하지 않는다. 모든 변경은 AI가 `deck_spec.json`을 수정해 재생성한다.
- 렌더러가 사용 가능하면 렌더링 기반 시각 검사를 필수로 수행한다.
- 렌더러가 없으면 최종 상태를 `partial`로 표시하고 시각 검사가 생략됐음을 사용자에게 알린다.

## `SKILL.md` 내용

- YAML frontmatter에는 `name`과 포괄적인 트리거 설명만 둔다.
- Claude Code와 Codex 양쪽에서 사용 가능하다는 점을 명시한다.
- 환경별 설치 위치와 호출 방법을 짧게 안내한다.
- 필요한 참조 문서를 언제 읽어야 하는지 직접 연결한다.
- 분석, 생성, 검사, 제한 반복의 순서를 명령형으로 설명한다.
- 구조 검사, 렌더 검사, 이미지 자동검사, 비전 에이전트 평가를 순서대로 실행한다.
- 비전 에이전트는 고정된 `visual-review-rubric.md`를 읽고 슬라이드별 근거를 JSON으로 남긴다.
- 저장소의 Windows용·macOS용 폰트 위치, OS별 수동 설치 절차, 사전 검사 방법을 명시한다.
- 저장소 포함과 PPTX 폰트 임베딩의 차이 및 `python-pptx`의 임베딩 한계를 명시한다.
- 특정 벤더 전용 도구 호출을 필수 절차로 넣지 않는다.
- 본문은 간결하게 유지하고 상세 규칙은 `references/`로 보낸다.

## `AGENTS.md` 동기화

`SKILL.md`의 공통 실행 본문을 정본으로 삼아 `AGENTS.md`를 생성한다. 생성 파일에는 직접 편집 금지 표식을 넣고, 동기화 테스트를 추가한다. 플랫폼별 심볼릭 링크 권한 문제를 피하기 위해 심볼릭 링크는 기본안으로 사용하지 않는다.

## 테스트

- 5개 필수 빌더가 각각 최소 한 장을 생성한다.
- 생성 파일을 `python-pptx`로 다시 열 수 있다.
- 코드에서 허용되지 않은 색상 hex가 직접 사용되지 않았는지 검사한다.
- 슬라이드 사이에 `brand.json`을 바꾼 테스트에서 다음 슬라이드부터 값이 반영된다.
- 효과 옵션의 기본값이 모두 꺼져 있다.
- Windows와 macOS 모의 환경에서 올바른 폰트 자산 경로가 선택된다.
- 미설치 폰트라도 검증된 임베딩 경로가 있으면 휴대 가능한 PPTX를 생성한다.
- 임베딩이 불가능하면 `portable-static.pptx`와 PDF를 생성하고 시각 정합성을 검사한다.
- `restyle-only`의 원문·수치·표·차트 데이터 보존과 슬라이드 대응표를 검사한다.
- `hana-refine`이 제공된 초안의 사실과 출처 범위를 벗어나지 않는지 검사한다.
- PowerPoint와 LibreOffice 렌더 백엔드 선택 및 manifest 기록을 검사한다.
- 잘림, 겹침, 여백 부족과 정렬 이탈이 있는 고의 불량 슬라이드를 검출한다.
- contact sheet와 슬라이드별 시각 평가 리포트가 생성된다.

## 완료 조건

- 표지, 목차, 텍스트+불릿, 비교, 클로징 생성이 가능하다.
- 샘플 출력이 생성되고 열림 검사를 통과한다.
- 외부에서 준비된 PPTX 또는 구조화된 초안이 선택한 후처리 워크플로에 따라 변환된다.
- 각 실행에서 `deck_spec.json`, PPTX, PDF와 미리보기 PNG가 생성된다.
- 렌더러가 있는 환경에서 결과 PPTX의 모든 슬라이드가 PNG로 생성되고 시각 검사를 통과한다.
- `SKILL.md`만으로 설치부터 생성까지 재현할 수 있다.
- `AGENTS.md`와 공통 본문의 동기화가 자동 검증된다.
