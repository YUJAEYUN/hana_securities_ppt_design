# 5. 품질 검사와 제한 반복

## 목적

브랜드 이탈을 자동으로 검출하고, 자동화하기 어려운 시각 품질은 사람이 일관되게 검토하게 한다. 수정 루프가 무한히 발산하지 않도록 명시적 정지 지점을 둔다.

## `quality_check.py` 검사 항목

### 색상

- 배경, 채우기, 선, 텍스트 색상을 정규화한다.
- `brand.json` 팔레트에 있는지 확인한다.
- 허용 오차는 명시적인 색상 거리 규칙으로 관리한다.
- 투명도와 테마 변형을 별도 표시한다.

초기 권장 정책은 핵심 브랜드색에는 정확 일치, 안티앨리어싱이나 이미지 분석이 개입되는 값에는 제한적인 오차 허용이다. PPT 도형 색상은 대개 정확한 값이므로 넓은 오차를 기본값으로 두지 않는다.

### 폰트

- 모든 텍스트 run의 폰트명을 검사한다.
- 상속되어 이름이 비어 있는 경우 테마와 마스터를 확인한다.
- 허용 폰트와 명시된 fallback을 구분한다.

### 로고

- 이미지 해시 또는 지정 자산과의 일치 여부를 확인한다.
- 크기와 위치를 슬라이드 대비 비율로 검사한다.
- 표지나 클로징 등 예외 유형은 별도 규칙으로 처리한다.

### 텍스트 오버플로우

정확한 렌더링 판정이 아니라 다음 요소를 조합한 근사 점수를 사용한다.

- 글자 수와 줄바꿈 수
- 폰트 크기와 행간
- 텍스트 박스 폭과 높이
- 언어별 평균 글자 폭 계수
- 불릿 들여쓰기와 문단 간격

명확한 위반은 `fail`, 경계 사례는 `warning`으로 출력한다. 리포트에 휴리스틱 한계를 반드시 표시한다.

## 리포트 형식

- 전체 결과: pass/fail
- 검사별 결과와 이유
- 슬라이드 번호와 도형 식별 정보
- 관찰값과 기대값
- 자동 수정 가능 여부
- 경고와 실패의 구분

JSON과 사람이 읽는 터미널 요약을 함께 지원하는 것을 권장한다.

## 고의 이탈 테스트

정상 샘플에서 다음 값을 하나씩 바꾼 픽스처를 만든다.

- 허용되지 않은 텍스트 색상
- 허용되지 않은 폰트
- 로고 위치 또는 크기 이탈
- 과도하게 긴 본문

각 픽스처가 예상 검사에서 실제로 실패해야 한다.

## 정성 체크리스트

`references/anti-slop-checklist.md`에는 다음을 포함한다.

- 정보 밀도가 기존 공식 양식과 비슷한가
- 제목과 본문의 시각적 위계가 자연스러운가
- 차트와 표가 데이터 전달에 적합한가
- 장식이 내용보다 강하지 않은가
- 문장 길이와 불릿 수가 과하지 않은가
- 슬라이드 간 정렬과 리듬이 일관적인가
- 실제 담당자의 블라인드 비교에서 이질감이 없는가

## 제한 반복 루프

1. 품질 검사를 실행한다.
2. 실패한 항목만 수정한다.
3. 새 결과를 `examples/YYYYMMDD-HHMMSS/` 등에 보존한다.
4. 이전 결과와 검사 리포트를 비교한다.
5. 최대 반복 횟수는 설정하되 3~5회 범위로 제한한다.
6. 제한에 도달하면 자동 수정을 중단하고 사람에게 결과와 남은 문제를 보여준다.
7. 사람 승인 없이 추가 반복을 시작하지 않는다.

## 완료 조건

- 정상 샘플은 핵심 검사에 통과한다.
- 고의 색상·폰트 이탈이 검출된다.
- 로고와 오버플로우 결과에 근거가 표시된다.
- 3~5회 후 정지하는 경로가 테스트된다.
- 정성 체크리스트로 담당자 검토가 가능하다.
