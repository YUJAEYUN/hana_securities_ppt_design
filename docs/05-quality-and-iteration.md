# 5. 품질 검사와 제한 반복

## 목적

브랜드 이탈을 구조와 렌더 이미지 양쪽에서 검출하고, 비전 에이전트와 사람이 동일한 루브릭으로 시각 품질을 검토하게 한다. 수정 루프가 무한히 발산하지 않도록 명시적 정지 지점을 둔다.

## `quality_check.py` 검사 항목

### 색상

- 배경, 채우기, 선, 텍스트 색상을 정규화한다.
- `brand.json` 팔레트에 있는지 확인한다.
- 허용 오차는 명시적인 색상 거리 규칙으로 관리한다.
- 투명도와 테마 변형을 별도 표시한다.

초기 권장 정책은 핵심 브랜드색에는 정확 일치, 안티앨리어싱이나 이미지 분석이 개입되는 값에는 제한적인 오차 허용이다. PPT 도형 색상은 대개 정확한 값이므로 넓은 오차를 기본값으로 두지 않는다.

### 폰트

- 모든 텍스트 run의 폰트명을 검사한다.
- 상속되어 이름이 비어 있는 경우 테마와 마스터를 확인한다.
- 허용 폰트와 명시된 fallback을 구분한다.
- PPTX에 기록된 패밀리명이 `brand.json`의 논리 폰트 역할과 일치하는지 검사한다.
- OS별 번들 파일의 존재 여부와 설치 여부는 `font_preflight.py` 결과로 별도 보고한다.
- `embed-preferred` 출력에서는 사용된 필수 패밀리가 실제 PPTX에 임베딩되었는지 검사한다.
- `portable-static` 출력에서는 정적 변환 범위와 시각 보존 결과를 리포트에 표시한다. 사용자 직접 편집 가능성은 평가하지 않는다.

### 콘텐츠 보존

- `restyle-only`에서는 원본과 결과의 문장, 수치, 고유명사, 표 셀과 차트 데이터를 비교하고 슬라이드 대응표의 완전성을 검사한다.
- `hana-refine`에서는 승인된 변경 계획 밖의 수정과 제공된 초안·출처에 없는 새 주장이 없는지 확인하고 변경된 문장을 목록으로 보고한다.

### 로고

- 이미지 해시 또는 지정 자산과의 일치 여부를 확인한다.
- 크기와 위치를 슬라이드 대비 비율로 검사한다.
- 표지나 클로징 등 예외 유형은 별도 규칙으로 처리한다.

### 텍스트 오버플로우

렌더러가 없을 때만 다음 요소를 조합한 근사 점수를 사용한다.

- 글자 수와 줄바꿈 수
- 폰트 크기와 행간
- 텍스트 박스 폭과 높이
- 언어별 평균 글자 폭 계수
- 불릿 들여쓰기와 문단 간격

렌더러가 있으면 출력 PNG에서 텍스트 잘림, 경계 접촉과 다른 요소와의 겹침을 우선 검사한다. 렌더러가 없는 휴리스틱 검사에서는 명확한 위반을 `fail`, 경계 사례를 `warning`으로 출력하고 그 한계를 표시한다.

## 렌더링 기반 시각 검사

### 렌더러 선택

1. Windows 데스크톱 PowerPoint를 사용할 수 있으면 이를 최종 기준으로 사용한다.
2. PowerPoint가 없으면 LibreOffice headless로 PDF를 만든 뒤 슬라이드별 PNG로 변환한다.
3. 사용한 렌더러, 버전, 화면 크기, 출력 해상도와 폰트 상태를 `render-manifest.json`에 기록한다.
4. 렌더러가 없으면 구조 검사만 실행하고 전체 결과를 `partial`로 표시한다.

### 결정적 이미지 검사

`visual_check.py`는 다음을 자동 검사한다.

- 슬라이드 가장자리에서 잘린 콘텐츠
- 요소 또는 텍스트의 비정상 겹침
- 콘텐츠와 슬라이드 경계 사이의 여백 부족
- 동일 유형 슬라이드 간 제목·로고·페이지 번호 위치 이탈
- 지나치게 비어 있거나 밀집된 영역
- 기준 이미지 집합과 비교한 색상 분포와 구성 지표의 이상치

픽셀 전체가 같은지를 비교하지 않는다. 콘텐츠가 달라지면 정상 슬라이드도 픽셀 차이가 크기 때문이다. 고정 요소의 좌표, 콘텐츠 경계, 밀도, 정렬과 색상 분포를 비교한다.

### 비전 에이전트 검사

`build_contact_sheet.py`가 전체 흐름을 볼 수 있는 contact sheet를 만들고, 에이전트는 개별 슬라이드 PNG와 함께 `references/visual-review-rubric.md`를 읽어 다음을 평가한다.

- 하나증권 브랜드와의 시각적 정합성
- 제목, 핵심 수치, 본문의 위계
- 여백, 균형, 정렬과 슬라이드 간 리듬
- 표와 차트의 가독성과 자연스러움
- 불필요한 카드, 그림자, 그라데이션 등 AI 티
- 정보 밀도와 임원 보고 자료로서의 신뢰감

평가 결과는 슬라이드 번호, `pass/warning/fail`, 문제 유형, 심각도, 근거와 권장 수정 범위를 가진 JSON으로 저장한다. 특정 AI API 호출은 Python 스크립트에 넣지 않고 현재 에이전트 환경의 이미지 이해 기능을 사용한다.

## 리포트 형식

- 전체 결과: pass/partial/fail
- 검사별 결과와 이유
- 슬라이드 번호와 도형 식별 정보
- 관찰값과 기대값
- 자동 수정 가능 여부
- 경고와 실패의 구분

JSON과 사람이 읽는 터미널 요약을 함께 지원하는 것을 권장한다.

## 고의 이탈 테스트

정상 샘플에서 다음 값을 하나씩 바꾼 픽스처를 만든다.

- 허용되지 않은 텍스트 색상
- 허용되지 않은 폰트
- 로고 위치 또는 크기 이탈
- 과도하게 긴 본문
- 슬라이드 경계에 걸친 제목 또는 본문
- 서로 겹친 텍스트와 도형
- 제목·로고 위치가 어긋난 슬라이드
- 지나치게 비어 있거나 밀집된 레이아웃

각 픽스처가 예상 검사에서 실제로 실패해야 한다.

## 정성 체크리스트

`references/anti-slop-checklist.md`와 `references/visual-review-rubric.md`에는 다음을 포함한다.

- 정보 밀도가 기존 공식 양식과 비슷한가
- 제목과 본문의 시각적 위계가 자연스러운가
- 차트와 표가 데이터 전달에 적합한가
- 장식이 내용보다 강하지 않은가
- 문장 길이와 불릿 수가 과하지 않은가
- 슬라이드 간 정렬과 리듬이 일관적인가
- 실제 담당자의 블라인드 비교에서 이질감이 없는가

## 제한 반복 루프

1. 구조 품질검사를 실행한다.
2. 결과 PPTX를 슬라이드별 PNG로 렌더링한다.
3. 이미지 자동검사와 비전 에이전트 검사를 실행한다.
4. 실패한 슬라이드의 실패 항목만 수정한다.
5. 새 결과, PNG, contact sheet와 JSON 리포트를 `examples/YYYYMMDD-HHMMSS/` 등에 보존한다.
6. 이전 결과와 검사 리포트를 비교한다.
7. 최대 반복 횟수는 설정하되 3~5회 범위로 제한한다.
8. 제한에 도달하면 자동 수정을 중단하고 사람에게 결과와 남은 문제를 보여준다.
9. 사람 승인 없이 추가 반복을 시작하지 않는다.

## 완료 조건

- 정상 샘플은 핵심 검사에 통과한다.
- 고의 색상·폰트 이탈이 검출된다.
- 두 후처리 워크플로의 콘텐츠 변경 경계와 출처 범위 위반이 검출된다.
- 폰트 임베딩 성공 여부가 검증되고 미검증 결과는 경고 또는 실패 처리된다.
- 로고와 오버플로우 결과에 근거가 표시된다.
- 모든 슬라이드 PNG, contact sheet, render manifest와 시각 검사 JSON이 생성된다.
- 고의 잘림·겹침·정렬 이탈·밀도 이상이 자동검사에서 검출된다.
- 비전 에이전트가 고정 루브릭으로 슬라이드별 시각 평가 근거를 남긴다.
- 3~5회 후 정지하는 경로가 테스트된다.
- 정성 체크리스트로 담당자 검토가 가능하다.
